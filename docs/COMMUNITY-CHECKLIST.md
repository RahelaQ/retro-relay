## The screenshot question

`screenshots/screenshot.png` is generated by `scripts/shoot.mjs`, which renders
a reproduction of Obsidian's layout in headless Chromium using the real
`theme.css`. The colours, borders, type and spacing are genuinely the theme's.
The window chrome is not a capture of a running Obsidian.

That is honest for the README, and it is what this session could produce —
Obsidian is a desktop app and cannot be run here. **Before submitting to the
directory, replace it with a real capture:**

1. Open `test-vault/` in Obsidian (the theme is already selected).
2. Open `Demo/Callouts.md` or `Demo/Typography.md`.
3. Capture the window and crop to 512 × 288.
4. Overwrite `screenshots/screenshot.png`.

Everything else in the repo is submission-ready as it stands.

## manifest.json

Required fields for a theme are `name`, `version`, `minAppVersion`, `author`.
Optional: `authorUrl`, `fundingUrl`.

`description`, `id` and `isDesktopOnly` are **plugin-only** fields — a theme
manifest carrying them is wrong. `scripts/build-release.mjs` fails the build if
any of them appear.

Current manifest:

```json
{
  "name": "Retro Relay",
  "version": "1.0.0",
  "minAppVersion": "1.5.0",
  "author": "RahelaQ",
  "authorUrl": "https://github.com/RahelaQ"
}
```

- [ ] **Decide on `author`.** It currently reads `RahelaQ` (your GitHub handle).
      Change it to your real name if you would rather be credited that way — it
      is the name shown in the theme browser. Update `LICENSE` and the README
      credit line to match.

These apply to the `name` field, not the repository name.

- [x] Does not contain the word "Theme" — themes may not.
- [x] Does not contain "Obsidian" or variants ("Obsi-", "-sidian").
- [x] Basic Latin only, no emoji or special characters.
- [x] Short and descriptive.

> **The theme name cannot be changed after the theme is published.** The
> repository name can be whatever you like — only the manifest is constrained.

## Release

Obsidian reads `manifest.json` from the HEAD of the default branch to find the
latest version, but downloads the actual files from the GitHub release whose
tag matches that version. Both are needed.

- [ ] `version` in `manifest.json` is `x.y.z` — currently `1.0.0`.
- [ ] Create a GitHub release tagged **`1.0.0`** (identical to the manifest
      version).
- [ ] Attach **both** files as binary attachments:
      `dist/manifest.json` and `dist/theme.css`
      (run `node scripts/build-release.mjs` to produce them).
- [ ] Release body: use `docs/RELEASE-NOTES-v1.0.0.md`.

```bash
node scripts/build-release.mjs

git tag 1.0.0
git push origin 1.0.0

gh release create 1.0.0 \
  --title "Retro Relay 1.0.0" \
  --notes-file docs/RELEASE-NOTES-v1.0.0.md \
  dist/manifest.json dist/theme.css
```

## Submitting

Submission is **no longer a pull request** against `obsidianmd/obsidian-releases`.
The current path:

1. Go to https://community.obsidian.md and sign in with your Obsidian account.
2. Link your GitHub account so the directory can verify you own the repository.
3. Sidebar → **Themes** → **New theme**.
4. Enter the repository URL.
5. Review and agree to the developer policies, and confirm you will support the
   theme.
6. **Submit.**

Review is automatic. To address feedback, push a fix and publish a **new
release with an incremented version** — the directory re-reads the manifest at
HEAD.

You only submit the first version. Later releases reach users automatically.
